# Оригинальные ресурсы и сохранение контента

Права на игру, её графику, звук, видео, тексты и скрипты сохраняются за
правообладателями. Проект не заявляет о полученном разрешении на публикацию
и не выдаёт лицензию на эти материалы. Наличие декомпиляции или требование
собственного EXE само по себе не разрешает распространять оригинальные ассеты.

## Как устроена текущая версия

- Для запуска игры пользователь предоставляет свой `QUEST.ezd` и 18 AVI-файлов.
- Studio читает заданный через `--archive` оригинальный архив без записи.
  Все исходные модели, текстуры, анимации и сцены остаются доступны редактору
  из этой локальной копии, а не скачиваются из репозитория.
- Исходный архив, образ диска, оригинальные EXE и инструменты Microsoft
  не включены в публичное дерево.
- В дереве пока есть извлечённые игровые скрипты в `src/scripts`, заголовки
  в `src/script_headers`, строки/таблицы в восстановленном коде, две исходные
  иконки в `src/lanes/codex/resources` и демонстрационные скриншоты.
  Они не становятся свободно лицензированными из-за текстового формата
  или размещения рядом с заново написанным кодом.

## Рекомендуемое разделение

| Содержимое | Как хранить |
|---|---|
| Собственная реализация движка, Studio, парсеры и конвертеры | В публичном репозитории с явно определённой областью лицензии |
| Форматы, имена записей, размеры, контрольные суммы, карты смещений | В манифестах и документации; без встроенного содержимого ассетов |
| Оригинальные модели, текстуры, анимации, видео, аудио, диалоги и скрипты | Сохранять из своей копии игры локально; подключать напрямую или извлекать утилитой |
| Новые авторские модели, текстуры и моды | Публиковать с разрешением авторов и указанием условий |
| Модификации сцены | По возможности сохранять как операции над объектами и ссылки на ресурсы пользовательской копии |
| Сторонние библиотеки | Со своими лицензиями и обязательными уведомлениями |

Так можно сохранить полный набор ресурсов для работы и исследования, не включая
его копию в каждый публичный клон. Предлагаемая схема извлечения: проверить
версию и SHA256 локального источника, сохранить структуру и дубликаты записей,
создать локальный манифест и держать извлечённые файлы вне Git. Перенос текущих
скриптов и иконок на генерацию/извлечение при настройке — следующий возможный
этап; это ещё не выполнено, и эти файлы автоматически не удалялись.

Studio сейчас экспортирует мод как ZIP с изменённым `QUEST.ezd`, который может
содержать и неизменённые оригинальные записи. Такой ZIP предназначен для
локальной проверки; это не автоматически подходящий формат для публичной
раздачи модов. Для раздачи удобнее отдельный формат изменений сцены, применяемых
к пользовательскому архиву. Даже дельта-патч может содержать оригинальный
контент: состав публикации всё равно нужно оценивать отдельно.

## Примеры других проектов

- [sdw-decomp — BUILDING.md](https://github.com/offx366/sdw-decomp/blob/main/BUILDING.md):
  пользователь предоставляет свою копию игры; редактор/инструменты читают `Levels/`,
  часть заголовков генерируется из файлов этой копии. EXE нужен для сборки/сверки,
  но сам по себе не заменяет файлы уровней. [NOTICE](https://github.com/offx366/sdw-decomp/blob/main/NOTICE.md)
  отделяет собственные работы проекта от прав на игру.
- [Super Mario 64 decompilation](https://github.com/n64decomp/sm64):
  перед сборкой пользователь предоставляет `baserom.<VERSION>.z64` для извлечения ассетов.
- [OpenRCT2](https://github.com/OpenRCT2/OpenRCT2):
  для игры требуются оригинальные файлы RollerCoaster Tycoon 2.

Эти примеры показывают технические способы организации проектов, а не
разрешение или юридическую гарантию для другого проекта. Правила GitHub
о рассмотрении претензий: [DMCA Takedown Policy](https://docs.github.com/en/site-policy/content-removal-policies/dmca-takedown-policy).
