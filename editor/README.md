# Титбит Studio — локальный редактор сцен

![Studio: свободная камера, сцена клуба и выделенный объект](../docs/images/studio.png)

**Проще всего:** скачайте `TitbitStudio.exe` из [Releases](https://github.com/offx366/titbit-modern/releases)
и запустите — он сам найдёт `QUEST.ezd` или спросит его один раз. Собрать exe самому:
`editoruild_studio.ps1` (нужен Python с зависимостями и `pyinstaller==6.11.1`).

Запуск из исходников, из корня публичного репозитория:

```powershell
.\.venv\Scripts\python.exe editor/server.py --archive "D:\Games\Titbit\QUEST.ezd"
```

Адрес: http://127.0.0.1:4318/. Установка Python и зависимостей: [BUILD.md](../docs/BUILD.md).
Для тестов задайте `TITBIT_GAME` — папку своей игры с `QUEST.ezd`, затем
`python -m unittest discover -s editor -p "test_*.py"`.
Все JS-зависимости находятся в `web/vendor`, интернет редактору не нужен.

## Работа

- Слева — 70 сцен из оригинального QUEST.ezd и созданные сцены проекта.
- ПКМ — свободное вращение камеры, средняя кнопка — панорама, колесо — приближение.
- ЛКМ — выбор объекта; его также можно выбрать в дереве. `F` — приблизить объект.
- `Q` — выбор, `W` — перемещение, `E` — поворот, `R` — масштаб. Манипулятор
  располагается в центре выбранного объекта. Числовые поля задают сдвиг центра,
  углы в градусах и масштаб. Доступны мировые/локальные оси и привязка.
- Справа — геометрия, исходные свойства, скелет/границы, XML и текст скрипта.
  В узком окне панель открывается кнопкой **Инспектор**.
- **Камера игры** — исходная камера с пропорциями 4:3. **Вся сцена** возвращает
  свободный обзор. Можно изменить параметры камеры или записать новый ракурс.
- Дублирование, удаление, пустые объекты, копия локации; `Ctrl+Z` и `Ctrl+Shift+Z`.
- `Ctrl+S` сохраняет проект в `editor/projects/default.json`. Предыдущая сохранённая
  версия остаётся в `default.previous.json`. Закрывая вкладку, сохраняйте изменения.

## Обмен с Blender и игровая сборка

**OBJ + материалы** скачивает ZIP с OBJ, MTL и PNG, в мировых координатах Z-up.
**GLB** содержит статическую геометрию и встроенные текстуры. FBX напрямую не
поддерживается; OBJ/GLB можно открыть в Blender и конвертировать там.

Импорт: одиночный OBJ (геометрия) либо GLB/glTF со встроенными ресурсами.
**Заменить модель…** возвращает изменённую в Blender статическую модель на место
исходного объекта, сохраняя его имя, свойства и скрипт. Используйте мировые
координаты экспорта редактора. Замена моделей с несколькими костями не поддерживается.
Оригинальные EZA-анимации проигрываются в нижней панели: вся сцена либо выбранный
объект, воспроизведение/пауза, перемотка, скорость и цикл. Начальные клипы берутся
из XML и ссылок ON_CREATE; доступны также связанные клипы из скрипта и библиотеки
модели. **Стоп** возвращает исходную XML-позу. Предпросмотр не меняет проект.
При открытии локации включаются исходная игровая камера 4:3, начальные клипы,
авторские плоскости/тени и частицы (включая огонь). Материалы учитывают родной
флаг прозрачности: RGB непрозрачного фона сохраняется даже при alpha=0.
Скриптовая VM, диалоги и выбор ветки по сохранённому квестовому состоянию здесь
не запускаются: условная начальная анимация — один из доступных вариантов входа.
AVI-компоненты и родные эффекты источников света пока не воспроизводятся;
предпросмотр анимаций не равен исполнению всей игровой сцены.
GLB экспортирует текущую статическую позу; анимационные дорожки в него не пишутся.
Прямые ссылки поддерживают `?scene=getto_bomj_n.xml`.
Анимации, скиннинг и морфинг импортируемых моделей отклоняются с объяснением;
редактор не превращает их в незаметно повреждённый игровой скелет.

**Экспорт сцены → Архив для игры** создаёт отдельный ZIP с изменённым QUEST.ezd,
описанием проекта и изменёнными XML/MEAT/MAT/TGA. Оригинальные записи архива,
включая дубликаты, сохраняются; меняется последняя одноимённая запись, как в игре.
Для проверки скопируйте файлы из `build/modern` в отдельную игровую папку и замените QUEST.ezd
только в ней. Автоматического запуска игры нет. Новая локация не получает
автоматически переходов из других локаций: их нужно задать в скриптах/свойствах.

Часть декораций оригинала — плоские текстурированные поверхности с заранее
отрисованным изображением. Свободный обзор показывает именно их устройство;
трёхмерной обратной стороны у такой декорации в исходных данных нет.

Изменения существующих объектов применяются к корневым костям, сохраняя их
иерархию и скрипты. Игровой формат не хранит shear; преобразование, которое
невозможно выразить его положением/поворотом/масштабом, отклоняется при экспорте.
GLB сохраняет видимый результат без такого ограничения. Скрытие в дереве —
видимость для редактора и GLB; для удаления из игры используйте **Удалить**.

## Проверка и устройство

`python -m unittest discover -s editor -p "test_*.py"` — 28 тестов:
побайтное чтение/запись всех 314 исходных MEAT, 161 MAT, 70 XML, сохранение
неизвестных компонентов, дубликаты EZD, преобразования скелета, импорт в игровые
форматы, OBJ/текстуры и повторное открытие собранного архива мода; все 455 EZA,
интерполяция поз, авторские начальные клипы и обнаружение анимаций из скриптов.

Сервер слушает только 127.0.0.1, отклоняет посторонние Host/Origin и не предоставляет
произвольного доступа к файловой системе. Оригинальный QUEST.ezd задаётся через `--archive` или `TITBIT_GAME`, запись возможна только
в отдельный проект/скачиваемый экспорт. Игра и дашборд не изменяются.

`formats.py` — форматы по восстановленным загрузчикам; `exporters.py` — OBJ и
нативный экспорт; `server.py` — локальный HTTP API; `web/` — Three.js интерфейс.
Версия Three.js закреплена в `vendor_three.py`, исходный пакет и SHA512 записаны
в `web/vendor/package-info.json`, лицензия — `web/vendor/LICENSE`.
